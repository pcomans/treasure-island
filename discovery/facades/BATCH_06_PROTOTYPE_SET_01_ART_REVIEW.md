# Batch 06 prototype set 01 — independent absolute art review

**Reviewed:** 2026-08-30  
**Reviewer:** art director (`/root/art_director`), independent of prototype authoring, capture, and mechanical validation  
**Evidence:** `evidence/first-playable/batch-06-prototype-set-01-2026-08-30/`  
**Targets:** `w34313564`, `w34313515`, `w291196370`  
**Evidence role:** controlled standalone render-only prototypes; not exact-receiver, live-attachment, gameplay, or whole-building evidence

## Final decision

**Five homogeneous fields: ACCEPT_WITH_SCALE_LIMITATION as standalone prototypes.**  
**Six complete modules: REJECT_CORRECTABLE as currently rendered.**

The fields preserve the observed target-specific value/color hierarchy, remain matte to low-satin, avoid facade-scale motifs, and stay stable at ordinary distance and under changed light. Their physical scales are reversible assumptions, not accepted measurements.

Every module contains the requested complete opening motif, but every module also places its field-colored outer surround on a shallow box in front of the proof wall. Those boxes create large rectangular facade panels, raised halos, or phase-reset siding patches that the observation ledger does not establish. `w34313564` additionally uses one fixed tan surround for `HWIN` and one fixed pale surround for `PDOOR` even though each module claims placement bounds spanning different side-color families.

No module is rejected for failing an opposite-edge seamless-tile test. These are complete bounded modules, and opposite-edge continuity is correctly declared false. They fail the absolute module gate because their complete surround is rendered as invented architecture rather than a coplanar continuation of the receiving field.

No lifecycle inventory, material, module, shader, scene, factory, registry, test, generated data, runtime attachment, or evidence file was changed by this review.

## Exact-receiver considerations

The two shared procedural shaders set `field_position_m = VERTEX.xy`. The standalone boards face the coordinate orientation on which this reads as one horizontal unit per metre. That does not prove horizontal physical scale across the multiple world-wall orientations mapped for these three targets. Before any exact-receiver art acceptance, use a target-specific wall-tangent/vertical metre projection or supply equivalent direct proof that one horizontal shader unit advances one physical wall metre on every tested orientation.

For `w291196370`, vertical course height derives from `VERTEX.y` and is stable on the board, but exact receiver evidence must also prove continuous `0.20 m` course phase across accepted runs and corrected module boundaries. A generated U restart is not a legal course or module seam.
